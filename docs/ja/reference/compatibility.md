# 互換性

Naos を更新しても変わらないもの、つまり、書いたもの、実行したもの、ビルドしたもの、読んだものが次のバージョンでも同じ結果になることを挙げます。リファレンスのほかのページは、今のバージョンの振る舞いを正確に書いたものです。そのバージョンの間は頼ってかまいませんが、後のバージョンで変わることがあり、そのときは変更履歴に書きます。

## どのバージョンの間か

次の約束は、あるバージョンから次のバージョンへ保たれます。

- 1.0 より前: `0.<minor>.<patch>` から、マイナーバージョンが同じ後のバージョンのどれへでも。
- 1.0 以後: `<major>.<minor>.<patch>` から、メジャーバージョンが同じ後のバージョンのどれへでも。

## 原則

- **約束するのは、このページに挙げたものだけです。** リファレンスに書いてあっても、このページに挙げていない細部は、後のバージョンで変わることがあります。
- **Naos はメジャーバージョンを上げずに厳しくなることがあります。** テストハーネスは誤りを見つけるためのものなので、前のバージョンが見逃していた誤りを、新しいマイナーバージョンが報告することがあります。通っていたテストが失敗したり、スイートがテストの実行前に拒まれたりします。パッチバージョンでは起きません。できる場合は、前の判定に戻すオプションを用意します（アサーションを実行しないテストに対する `--naos-allow-no-assertions` のように）。逆に、失敗していたものを通すようにする変更は、互換を壊す変更です。
- **必要なものは知らせてください。** このページが約束していないものに頼る使い方がある場合は、issue を立ててください。後のバージョンでそれを約束するか、約束する手段を足すことがあります。

## テストを書く

書いたテストは、同じようにコンパイルでき、同じように動きます。

- [テストとスイート](tests.md)、[アサーション](assertions.md)、[失敗、スキップ、メモ](control.md)、[バージョン](version.md)のマクロと関数と、その引数。`#include <naos/naos.h>` で使えること。
- 各アサーションがいつ成功し、いつ失敗するか。引数をそれぞれちょうど 1 回だけ評価すること。
- 失敗したときの動き。`NAOS_CHECK*` はテストを続け、`NAOS_REQUIRE*`、`NAOS_FAIL`、`NAOS_SKIP` はテストを止めます。
- 実行の順序。スイートは登録した順、スイートのテストは並べた順に実行し、各テストの前に setup、後に teardown を実行します。setup や本体が途中で止まっても teardown は実行します。
- テストの結果の決まり方。setup、本体、teardown のどこで失敗してもテストは失敗し、失敗なしにスキップすればスキップです。[失敗するはずのテスト](control.md#失敗するはずのテスト)は、失敗している間は成功、成功したら失敗です。
- マクロが定義する名前 `naos_gen_<役割>_<名前>`。デバッガとスタックトレースに出る名前です。
- [独自の `main()`](tests.md#独自の-main)。`naos_init()`、`NAOS_ADD_SUITE`、`naos_run()` と、その順序。

## テストを実行する

動いていたコマンドは、同じ意味のまま動きます。

- オプション `--naos-*` と `--help`、その値、`--naos-<オプション>=<値>` の形（[コマンドライン](command-line.md)）。
- `--naos-filter` のパターン。`*`、`?`、`:`、`-`。
- [終了コード](command-line.md#終了コード) `0`、`1`、`2`、`77` と、それぞれの意味。
- `--naos-list`。名前 `<suite>.<test>` を 1 行に 1 つ、登録した順に出力すること。
- `--naos-shuffle` で `--naos-random-seed` に与えたシードは、Naos の同じバージョンで同じテストを選んでいれば、どのプラットフォームでも同じ順序をもう一度実行します。

## 結果を読む

結果を読むツールは、そのまま動きます。

- `--naos-output xml:<path>` の [JUnit XML](xml.md) のファイル。ファイルを書くとき、要素とその入れ子、どのテストケースと、どの `<failure>`・`<skipped>` を書くか、属性 `name`、`classname`、`tests`、`failures`、`errors`、`skipped`、`time`、`file`、`line`、`type`。属性 `message` はリファレンスに書いた場所にありますが、その中身は約束しません。
- 結果を書く前に実行が終わったとき（クラッシュ、`exit()`、時間制限）は、`<error>` を持つファイルが残り、ツールはそれをエラーとして数えます（[プレースホルダー](xml.md#プレースホルダー)）。そのテストケースの名前と中身は約束しません。
- 標準出力の診断の行の始まり。エディタや problem matcher が読むものです。その形式の[場所](output.md#診断の行)（または `naos: `）、続く `error`、`skip`、`note` と `: `（[失敗した行をエディタで開く](../guides/ctest-and-ci.md#失敗した行をエディタで開く)）。
- 終了コード（上と同じ）。

## ビルドする

動いていたビルドは、そのまま動きます。

- パッケージ `Naos`。[CMake](cmake.md#パッケージ) のとおり `find_package(Naos <version>)` で見つかること、`FetchContent` や `add_subdirectory()` で足せること、ターゲット `Naos::naos`。
- `naos_add_executable()` と `naos_discover_tests()` と、その引数（[CMake](cmake.md#関数)）。
- それらが CTest に登録するテスト。名前は `<prefix><suite>.<test>`（prefix の既定は `<target>.`）で、スキップしたときは CTest がスキップとして数え、与えたラベルとプロパティを持ちます。実行ファイルをビルドするまでは、代わりに失敗するテストが 1 つあります。
- オプション `NAOS_SELFTEST`、`NAOS_INSTALL`、`BUILD_SHARED_LIBS`（[CMake](cmake.md#オプション)）。
- CMake を使わない場合。`pkg-config` のモジュール `naos` と、そのフラグでテストをビルドしリンクできること。ライブラリの名前 `naos`（Debug ビルドは `naosd`）（[インストール](../getting-started/installation.md#ほかのビルドシステム)）。

## 共有ライブラリ

- あるバージョンでビルドしたテストの実行ファイルは、`SOVERSION` が同じ後のバージョンの共有ライブラリで動きます。`SOVERSION` は 1.0 より前は `0.<minor>`、1.0 以後は `<major>` です（[CMake](cmake.md#ターゲット)）。
- マクロが使う関数、型、補助マクロ（`naos_check_int()` など）は、そのためだけに保ちます。自分のコードでは使わないでください。マクロがそれらをどう使うかは変わることがあります。

## 互換を保たないもの

次のものは、どのバージョンでも変わることがあります。知っておけば、これらに頼らずに済みます。

- **診断の行の始まりを除く標準出力。** 流れの行（`RUN:`、`PASS:`、`SUMMARY:` など）、詳細の行、その並びは人が読むためのもので、読みやすくするために変わります。ツールは代わりに JUnit XML のファイルを読んでください。
- **Naos が書く文言。** 診断の行の種類より後の内容、ヒント、標準エラー出力の `naos: ` のメッセージ、`--help` の出力、`<failure>` の中身とその `message`。これらで照合しないでください。
- **別のバージョンでシードが与える順序。** ある順序をもう一度実行するには、そのシードを出力したバージョンの Naos を使ってください。
