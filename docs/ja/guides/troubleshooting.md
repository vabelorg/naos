# トラブルシューティング

症状から引く、よくある問題とその原因です。

## コンパイルとリンク

**`NAOS_SUITE` や `NAOS_MAIN` でエラーになる、または余分な `;` の警告が出る**

- `NAOS_SUITE` や `NAOS_MAIN` の最後の項目の後ろにカンマがあるとコンパイルできません。取り除きます。
- `NAOS_TEST(...) { }`、`NAOS_SUITE(...)`、`NAOS_MAIN(...)` の後ろに `;` は付けません。付けると `-Wpedantic` が警告します。
- `NAOS_DECLARE_SUITE(name);` には `;` が必要です。
- `NAOS_SUITE` の項目の間に `#ifdef` は書けません。プラットフォームごとのテストは別のスイートにして、スイート全体を囲みます（[スイート](../reference/tests.md#スイート)）。

**スイートが二重に定義されているというリンクエラー**

1 つの実行ファイルに同じ名前のスイートが 2 つあります。スイートの名前は実行ファイルの中で、テストの名前はファイルの中で重複しないようにします。

**スタブを使うと、関数が二重に定義されているというリンクエラー**

本物の関数がスタブと一緒にリンクされています。たいていは、本物を含むライブラリをリンクしているためです。そのライブラリをリンクする代わりに、テスト対象のソースを直接並べます（[スタブ](stubs.md#制約)）。

**`NAOS_FAIL` の後に `return` がないという警告が出る**

GCC、Clang、MSVC は `NAOS_FAIL` が戻らないことを知っていますが、ほかのコンパイラは警告することがあります。動作は変わりません。警告を消すには `return` を足します。

## 実行

**テストが実行されない**

どのスイートにも並べていないか、そのスイートを `main()` で登録していません。`--naos-list` で確かめます。スイートに並べていないテストは、コンパイラの未使用関数の警告でも分かります。

**終了コードが 2 で、標準エラー出力にメッセージが出る**

使い方エラーです。未知の `--naos-*` オプション、値がない・範囲外の値、どのテストにも一致しないフィルタ、スイートの誤り（同じ名前を 2 回使った、setup を 2 回指定した）のどれかです。誤りは、テストを実行する前にすべて報告されます（[終了コード](../reference/command-line.md#終了コード)）。

**終了コードが 77**

実行したテストがすべてスキップでした。CTest は失敗ではなくスキップとして数えます。

**単独では通るのに一緒に実行すると失敗する（またはその逆）**

テストが別のテストの残した状態に依存しています。`static` 変数の値はテストの間で引き継がれます。`--naos-shuffle` と固定した種で組み合わせを見つけ、その状態を setup でリセットします（[テストの実行](running-tests.md#テストの間の依存を見つける)）。

**クラッシュや無限ループで、実行全体が終わる・終わらない**

すべてのテストが 1 つのプロセスを共有しています。テストごとにプロセスを分け、`--timeout` を付けられる CTest で実行します（[CTest と CI](ctest-and-ci.md)）。最後に出力された `RUN:` の行が、実行中だったテストです。

**C++ のテストでオブジェクトが破棄されない**

テストを止めるマクロは `longjmp` で抜けるので、デストラクタは呼ばれません。デストラクタを持つオブジェクトは、止まりうる関数の外に置きます（[C++](cpp.md)）。

## CMake と CTest

**`ctest` がテストを見つけない**

トップレベルの `CMakeLists.txt` に `enable_testing()` か `include(CTest)` がないか、`ctest` を違うディレクトリで実行しています（`--test-dir build` を使います）。

**CTest に `<target>.NOT_BUILT` が出て失敗する**

実行ファイルがまだビルドされていないか、`-C` で選んだ構成（マルチコンフィグのジェネレータ）でビルドされていません。その構成でビルドしてから、もう一度 `ctest` を実行します。

**ビルドが「Discovering Naos tests」で失敗する**

ビルド後のテストの列挙に失敗しています。メッセージに理由が出ます。

- 制限時間を超えた: エミュレータの下などでは `DISCOVERY_TIMEOUT` を延ばします（[CMake](../reference/cmake.md#naos_discover_tests)）。
- 共有ライブラリが見つからない: Windows では、出力なしで `Exit code 0xc0000135` となります。列挙の前に、DLL を実行ファイルの隣か `PATH` の通った場所に置きます（[共有ライブラリ](shared-library.md#ビルド時に-dll-が見つかるようにする)）。

**`find_package(naos 0.1)` がインストールしたバージョンを受け付けない**

1.0 より前は、0.1.x だけを受け付けます。プロジェクトが求めるマイナーバージョンをインストールするか、プロジェクトの側を更新します。

**コマンドラインの引数で足したテストが CTest にない**

CTest に登録されるのは、引数なしで列挙されるテストです。引数を付けて実行ファイルを直接実行します（[独自の main()](custom-main.md)）。

## エディタ

**VS Code が失敗を拾わない**

`$gcc` は GCC 形式の `file:line: error:` を読みますが、MSVC でビルドした Naos は `file(line): error:` を出力し、`$msCompile` はこれを読みません。両方を読む [CTest と CI](ctest-and-ci.md#失敗した行をエディタで開く) の problem matcher を使います。
