# 文書の書き方

Naos の文書の構成と書き方です。ページを足したり変えたりする前に読んでください。

## 言語

- 英語が正です。どのページもまず英語で、`docs/`（と `README.md`。`CONTRIBUTING.md`、`SECURITY.md`、`CODE_OF_CONDUCT.md` も `docs/` にあります）に書きます。
- 日本語は全体の翻訳です。`docs/ja/` は `docs/` をファイルごとに同じ名前で写し、`README.ja.md` は隣にある英語のファイルを訳したものです。`docs/ja/CODE_OF_CONDUCT.md` は Contributor Covenant の公式の日本語訳で、Naos が訳したものではありません。
- 英語のページの変更は、翻訳を待ちません。翻訳は後のプルリクエストで追いつけばよく、英語の言い回しを直すだけの変更には翻訳は要りません。
- `CHANGELOG.md` は英語だけで、日本語訳はありません。
- コードのコメントは、ソースでも `examples/` でも英語だけです。訳したページでは、コード例のコメントも訳します。コードそのものとファイル名はそのままにします。

## ページの置き場所

ページは 3 種類に、開発者向けの 4 つ目を加えた区分に従います。1 つのページは 1 つの種類に属し、別の種類の内容が必要ならリンクします。

| ディレクトリ | 種類 | ページの役割 |
|---|---|---|
| `getting-started/` | チュートリアル（学ぶ） | 初めての人を、動く結果まで 1 歩ずつ案内する |
| `guides/` | ハウツー（やる） | 基本を知っている人の、1 つの課題を解く |
| `reference/` | リファレンス（調べる） | API の 1 つの部分の規則を、漏れなく正確に書く |
| `development/` | 開発者向け | ビルド、アーキテクチャ、テスト、書き方、リリース |

規則はリファレンスに 1 度だけ書きます。ガイドやチュートリアルは使い方を示し、規則を全部繰り返さずにリファレンスへリンクします。

## 書き方

- 短い文、現在形で、読む人に向けて書く。
- 見出しは、ガイドなら課題を（「一部のテストだけを実行する」）、リファレンスなら対象を（「終了コード」）表す。英語の見出しは sentence case。
- コード、名前、オプション、パス、出力はバッククォートで囲む。
- 1 つの概念には 1 つの用語を使い、同じものは全体で同じ言葉で呼ぶ。
- コードが守らない約束は書かない。動作として書くことは、自己テストで確かめているか、自己テストから引用したものにする。

## コードと出力

- 数行を超えるコードの例は、自己テストがビルドして実行する `examples/` から取る。そこからコピーし、サンプルが変わったらページも直す。
- 実行の結果として示す出力は、実際の実行からコピーする。なるべく `tests/examples/expected/` のゴールデンファイルから取る。場所は GCC 形式で、ファイル名だけにする（`clamp_test.c:10:`）。
- 完全なプログラムでない短い断片は手で書いてよいが、API に正確に従う。

## リンク

- ページ間のリンクは相対パスにする（`../reference/cmake.md#オプション`）。GitHub でも、手元の複製でも動くようにするため。
- 節へのリンクは、GitHub が見出しに付ける id を使う。小文字にし、句読点を除き、空白を `-` にしたもの。見出しを変えるとそこへのリンクが切れるので、自己テスト `naos.docs.links` で見つける。
- 文書を指すコードのコメントや CMake のファイルは、英語のページを指す。
